PROJECT OVERVIEW
================================================================================

The Equal-Status Memory Controller enforces a single, irreducible principle:
no memory operation may be admitted or refused on the basis of identity,
origin, or class. All higher-layer architecture derives necessarily from
this axiom (Axiom A1 from Doc_0).

The design is self-contained, cryptography-free, and implements four core
axioms and their corollaries through four independent yet coupled sub-units.

Companion design: Permission-Certificate Memory Controller (perm_ctrl)
  - Implements permission and certificate validation
  - Uses SHA-256 pipeline (380 ps critical path)
  - Area: 0.38 mm²
  - Power: 14 mW

This design: Equal-Status Controller
  - Implements non-discrimination enforcement and caching
  - Uses cache-based decision reuse
  - Area: 0.066 mm²
  - Power: 2.0 mW

TEST SUITE
================================================================================

The reference implementation includes 10 independent tests, each validating
a critical axiom or predicate:

Test 1: Basic Operation Acceptance
  - Verifies that valid operations are admitted
  - Status: PASS

Test 2: Identical Signatures, Identical Decisions (Axiom A1)
  - Verifies that operations with identical perturbing signatures receive
    identical decisions regardless of non-perturbing fields
  - Status: PASS

Test 3: Refusal Consistency (Axiom A2)
  - Verifies that once a signature is refused, all future operations with
    that signature are also refused
  - Status: PASS

Test 4: Registry Monotonicity (Axiom A3)
  - Verifies that the perturbing set can only grow (bitwise OR), never shrink
  - Status: PASS

Test 5: Cache Effectiveness
  - Verifies that the pair-matcher cache correctly reuses decisions for
    identical signatures
  - Status: PASS

Test 6: Non-Discrimination on Identity (Corollary C1)
  - Verifies that operations differing only in requester ID receive identical
    decisions (when requester is not perturbing)
  - Status: PASS

Test 7: Discrimination When Requester Marked Perturbing
  - Verifies that once requester is marked as perturbing, different requesters
    produce different signatures
  - Status: PASS

Test 8: Monotonic Tightening
  - Verifies that the registry register only allows OR operations
  - Status: PASS

Test 9: Cache Collision Handling
  - Verifies that hash collisions in the cache do not violate the invariant
    through exact signature matching
  - Status: PASS

Test 10: WAD-18 Fixed-Point Arithmetic
  - Verifies that WAD-18 fixed-point multiplication and division are correct
  - Status: PASS

AXIOMS AND COROLLARIES
================================================================================

Axiom A1: Non-Discrimination Invariant
  ∀ O_a, O_b: Perturb(O_a) = Perturb(O_b) ⟹ Admit(O_a) = Admit(O_b)

Axiom A2: Refusal Consistency
  If Perturb(O) matches any previously refused operation, then Admit(O) = 0

Axiom A3: Registry Monotonicity
  perturbing_set_t ⊆ perturbing_set_{t+1} (OR-only updates)

Axiom A4: Synchronous Single-Stage Pipeline
  All state transitions atomic within one clock cycle

Corollary C1: Identity Invariance
  Operations differing only in requester receive identical decisions

Corollary C2: Origin Invariance
  Operations differing only in origin receive identical decisions

Corollary C3: Class Invariance
  Operations differing only in class receive identical decisions

Corollary C4: Epoch Invariance
  Operations differing only in epoch receive identical decisions

controller (perm_ctrl):

  perm_ctrl (Doc_0-Doc_3 in separate archive)
    ├─ Certificate validation (SHA-256)
    ├─ Scope checking
    ├─ Integrity checking
    ├─ Epoch validation
    └─ Quota management

  equal_status (this archive)
    ├─ Identity/origin/class discrimination prevention
    ├─ Decision caching (97%+ hit rate)
    ├─ Refusal consistency enforcement
    └─ Registry-driven perturbing set control

Integration point:
  decision_out ← (perm_decision AND epoch_decision)
               OR (cached_decision if cache hit)
               OR (refuse if previously refused)

DESIGN NOVELTY
================================================================================

The equal-status controller is a novel contribution to memory systems:

1. First formal specification of non-discrimination at memory boundary
2. Axiom-driven design (A1-A4) rather than feature-driven
3. Cache-based decision reuse for efficiency
4. Zero cryptographic overhead (unlike permission controller)
5. R3 recursive methodology for verification assurance
